## 是什么

Firecrawl 是一个面向 AI Agent 的网页抓取服务。传统爬虫拿到的是充满广告、导航栏、脚本标签的脏 HTML，LLM 直接消费代价高昂且噪声大。Firecrawl 解决的核心问题是：**从任意 URL 取回干净的、LLM 可直接使用的 Markdown 内容**。

它支持 JavaScript 渲染页面（SPA、动态加载）、整站批量爬取、内容结构化提取，并提供托管 API 和自托管两种使用方式。2024 年凭借极简的开发者体验迅速成为 AI Agent 生态中使用最广泛的网页数据层之一。

## 核心功能

| 功能 | 说明 |
|------|------|
| **Scrape（单页抓取）** | 传入 URL，返回清洗后的 Markdown / HTML / 截图，自动处理 JS 渲染 |
| **Crawl（整站爬取）** | 从起始 URL 出发递归爬取整站，支持深度/域名/路径过滤 |
| **Map（站点地图）** | 快速枚举一个域名下所有可访问 URL，不做内容抓取 |
| **Search（网页搜索）** | 结合搜索引擎返回相关页面并同步清洗内容 |
| **Extract（结构化提取）** | 基于 LLM 从页面中提取指定 JSON Schema 的结构化字段 |
| **Batch Scrape（批量抓取）** | 并发抓取多个 URL，适合大规模数据集构建 |
| **Watch（变更监听）** | 监听指定页面内容变化，触发 Webhook 通知 |

## 与其他爬虫方案对比

| 维度 | Firecrawl | 传统爬虫（Scrapy/Requests） | Playwright/Puppeteer |
|------|-----------|--------------------------|----------------------|
| **输出格式** | 干净 Markdown，LLM 可直接使用 | 原始 HTML，需二次处理 | 原始 HTML / 截图 |
| **JS 渲染** | 原生支持 | 不支持 | 原生支持 |
| **开发成本** | 极低，API 调用即用 | 高，需自行写解析逻辑 | 中，需维护浏览器会话 |
| **反爬处理** | 内置代理轮换、绕过机制 | 手动处理 | 部分支持 |
| **LLM 集成** | 一等公民，有 LangChain/LlamaIndex 插件 | 无 | 无 |
| **自托管** | 支持（Docker） | 完全自主 | 完全自主 |
| **托管服务** | 有，按量计费 | 无 | 无 |

## 适合场景

- **RAG 知识库构建**：将文档站、官网、博客批量转为 Markdown 喂给向量数据库
- **Agent 实时研究**：Agent 执行任务时临时抓取网页获取最新信息
- **竞品/行业监控**：定期爬取目标站点，结合 LLM 做内容对比分析
- **产品文档索引**：将第三方产品文档抓取并索引，构建专属问答机器人
- **新闻/舆情聚合**：批量抓取新闻源，清洗后做摘要或情感分析
- **数据集制作**：为 LLM 微调或评测构建大规模网页文本数据集

## 注意事项

- **协议限制**：AGPL-3.0，商业自托管部署需注意协议合规；托管 API 按量收费
- **反爬能力有限**：对强验证码（如 reCAPTCHA v3）、登录墙后的内容处理能力有限
- **爬取速度**：整站 Crawl 受限于目标站点速率，大站爬取耗时较长
- **内容准确性**：Markdown 转换对复杂表格、多列布局的还原度一般，需要验证
- **自托管复杂度**：完整自托管需要 Redis、Playwright 等依赖，资源消耗不低
- **Extract 依赖 LLM**：结构化提取功能会额外调用 LLM，增加延迟和成本
