## 是什么

UI-TARS-desktop 是字节跳动开源的**多模态 GUI Agent 完整应用栈**，核心是 UI-TARS 视觉语言模型——它专门为 GUI 操作训练，能识别任意平台（Windows、macOS、Web、移动端）的界面元素，像人一样点击、输入、拖拽。

不同于 browser-use 只针对浏览器，UI-TARS 可以操控桌面应用、跨应用流程（如从网页复制内容粘贴到 Excel），是真正的"电脑使用 Agent"。

## 核心架构

| 组件 | 作用 |
|------|------|
| **UI-TARS 模型** | 专为 GUI 操作训练的视觉语言模型 |
| **屏幕感知** | 实时截图 + 元素识别，理解当前界面状态 |
| **动作执行** | 模拟鼠标点击、键盘输入、滚动等操作 |
| **任务规划** | 将高层任务分解为可执行的 GUI 操作序列 |
| **桌面应用** | 基于 Electron 的跨平台桌面界面 |

## 核心功能

- **跨平台 GUI 控制**：Windows、macOS 桌面应用 + 浏览器统一控制
- **零 API 接入**：直接操作界面，不依赖目标应用提供 API
- **多步骤任务**：自动完成跨多个应用的复杂工作流
- **本地模型支持**：UI-TARS 模型可本地部署，数据不出本机
- **实时可视化**：操作过程实时展示，支持人工干预

## 与 browser-use 对比

| 维度 | UI-TARS-desktop | browser-use |
|------|----------------|-------------|
| 控制范围 | 全桌面（含桌面应用） | 仅浏览器 |
| 感知方式 | 纯视觉（截图） | 视觉 + DOM |
| 模型 | 专用 GUI 模型 | 通用视觉 LLM |
| 本地部署 | 支持 | 需要外部 LLM |
| 精准度 | 依赖视觉识别 | DOM 更精准 |

## 适合场景

- **跨应用自动化**：需要同时操控多个桌面软件的工作流
- **遗留系统自动化**：没有 API 的老旧应用的自动化操作
- **数据录入**：从多个来源收集数据录入特定系统
- **GUI 测试**：模拟真实用户操作的端到端测试

## 注意事项

- 纯视觉感知对界面渲染质量有要求，低分辨率或小字体可能识别出错
- 本地模型需要较高配置（推荐 16GB+ 显存）
- 操作速度比 API 驱动的自动化慢，不适合高频任务
